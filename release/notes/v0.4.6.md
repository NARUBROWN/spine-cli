# Spine CLI v0.4.6

## v0.4.6-preview.1

Spine 프리뷰 앱에서 `WithShutdownHook`를 등록하면 `spine verify`가 어댑터를 확인할 수 없다고 판단하던 문제를 수정합니다.

- HTTP와 WebSocket 어댑터 정적 검사는 `spine.WithShutdownHook(callback)`을 인식합니다. 콜백과 DI 의존성을 실행하지 않고 옵션 형식만 확인합니다.
- 이벤트 구독에 사용한 다른 패키지의 문자열 상수는 소스와 의존성을 읽어 해석합니다. Go 1.27에서 기존 분석 라이브러리가 컴파일된 타입 정보를 해석하지 못하던 문제를 해결합니다.
- 프리뷰 코어의 생성자 `error` 반환, 종료 훅 DI 주입, 앱 수명의 `publish.Publisher`와 조건부 OpenAPI의 런타임 내보내기를 회귀 검사합니다.
- 정적 DI 검사는 선택된 코어의 실제 선언에서 동기 `publish.Publisher` 계약을 확인합니다. 사용자가 제공자를 등록하지 않아도 이 타입과 별칭을 주입할 수 있으며, 사용자 인터페이스의 구조적 매칭과 제공자 모호성은 런타임 규칙을 따릅니다. 같은 이름의 사용자 타입을 앱 제공 타입으로 간주하지 않습니다.
- 앱이 제공하는 `publish.Publisher`를 반환하는 생성자는 `EVENT_PUBLISHER_RESERVED`로 거부합니다. 플랫폼은 `WithEventAdapter`로 등록합니다. 발행 플랫폼이 없어도 DI 타입은 제공되며 실제 발행에서 `publish.ErrUnavailable`이 반환됩니다.
- 브로커 fixture는 DI 메서드 호출로 이전하고 전송 오류를 반환합니다. 테스트 대상의 실제 코어 선언에 따라 이전 타입 기반 API, 큐에 JSON 필드를 적재하는 API와 새 DI API를 구분합니다. 같은 프리뷰 버전을 로컬 소스로 교체한 경우도 실제 계약을 사용합니다.
- Kafka, RabbitMQ와 NATS 프리뷰 모듈로 생성한 앱에서 발행 목적지 설정과 `verify`를 검사합니다. 목적지 목록이 없으면 소비 전용으로 설정하고, 목록 안의 빈 항목은 거부합니다. 이 검사는 실제 브로커 연결이나 송수신을 확인하지 않습니다.

## 소스 후보 검증

새 DI Publisher 코어는 아직 로컬 소스 후보이므로 공개 태그 설치 결과와 구분해서 검사합니다. 코어 경로를 지정하면 `verify`, DI 주입, 전송 결과 대기, 오류 전파와 Outbox 메타데이터를 검사합니다.

```sh
SPINE_CONTROLLER_CORE_SOURCE=/absolute/path/to/spine \
  go test -race ./internal/cli -run '^TestPreviewLifecycleCandidateEndToEnd$' -count=1
```

실제 브로커에서 생성 앱을 검사하려면 각각 `SPINE_TEST_KAFKA_BROKER`, `SPINE_TEST_RABBITMQ_URL`, `SPINE_TEST_NATS_URL`을 지정하고 `TestPublisherCandidateBrokerE2E`와 `TestPublisherCandidateNATSE2E`를 실행합니다. Broker 검사는 설정된 브로커만 실행합니다. 기본 공개 코어 생성 검사는 별도로 유지합니다.
