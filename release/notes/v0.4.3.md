# v0.4.3-preview.5: 컨트롤러 경로와 역할별 생성자 등록

이번 준비 후보는 `v0.4.3-preview.5`이며 아직 공개 발행하지 않았습니다. 코어 `v0.7.0-preview.5` 후보와 함께 검증합니다. 기존 `v0.4.3-preview.4` 태그를 재사용하지 않습니다.

- 새 코어 대상 생성기는 컨트롤러의 `RegisterRoutes(*api.Registry)`에 경로와 콜백을 작성합니다. 기존 코어의 `route.go` 방식은 유지하며 사용자 파일을 임의로 삭제하지 않습니다.
- `app.Constructor(...)`에 `constructor.Custom`, `Repository`, `Service`, `Controller`, `Interceptor` 표식을 모읍니다. CLI는 공식 import 경로와 별칭, 생성 메서드와 역할 계약, 의존성을 분석합니다.
- `input.Path[T]`, `input.Query[T]`, `input.Body[T]`의 DTO와 외부 필드 이름을 정적 계약과 OpenAPI에 반영합니다. 수동 검증 규칙이나 동적 상태 코드를 추측하지 않습니다.
- 기존 Constructor 호출과 import 별칭을 보존하며 표식을 독립된 줄에 추가합니다. dry-run, diff, base_hash와 --if-match, 재실행 시 unchanged 동작을 유지합니다.
- 정적 분석은 생성자나 init을 실행하지 않습니다. 새 컨트롤러의 런타임 export는 준비 전 명시적 오류를 반환하며 DB 연결을 위해 Prepare를 자동 실행하지 않습니다.

로컬 소스의 race, vet, 생성 앱의 실제 HTTP와 별도 User DB E2E 검증을 완료했습니다. 이 기록은 세 OS 공개 설치, 원격 CI, 태그 발행이나 release-manifest 검증을 대신하지 않습니다. 발행은 기존 Preview 승인 절차를 따릅니다.

## 이전 Preview 4: 이벤트와 validator 동적 조회

`v0.4.3-preview.4`의 이벤트와 validator 동적 조회 기능을 유지합니다. 기존 공개 태그는 변경하지 않습니다.

- `--event-platform [name:]provider`는 `NARUBROWN/spine-<provider>-platform@preview`, `--validator provider`는 `NARUBROWN/spine-validator-<provider>@preview`를 조회합니다.
- 선택 버전의 `spine-platform.json`에서 생성자, 설정 필드와 최소 Go 버전을 읽습니다. 새 provider는 메타데이터 규칙을 따르면 CLI 수정 없이 연결할 수 있습니다.
- 저장소/Preview 조회 실패와 메타데이터 누락을 구분해 경로와 원인을 표시합니다. 조회 실패는 프로젝트 파일을 만들기 전에 끝납니다.
- NATS JetStream 생성 앱과 미등록 이벤트 및 설정형 validator의 실제 브로커 E2E를 CI 필수 검사에 추가합니다. 기존 Kafka, RabbitMQ와 playground의 메타데이터 없는 버전은 호환 경로를 유지합니다.
- NATS 플랫폼의 첫 출시 후보는 `v0.1.0-preview.1`입니다. CLI의 Preview 조회는 태그 유무와 별개로 현재 `@preview`의 정규 버전을 기록합니다.

## 기존 후보와 동작

Preview CLI는 `go install github.com/NARUBROWN/spine-cli/cmd/spine@preview`로 설치할 수 있습니다. Go가 해석한 태그 또는 pseudo-version을 표시하며 로컬 빌드는 `0.4.3-dev`로 구분합니다.

`v0.4.3-preview.1`은 공식 설치 경로와 생성 문서의 명령 표기 회귀로 폐기했습니다. 해당 원격 태그를 삭제했으며 재사용하지 않습니다. 이전 후보는 `go install github.com/NARUBROWN/spine-cli/cmd/spine@v0.4.3-preview.3`로 설치하고 `spine`으로 실행합니다.

Preview, RC, Production을 순서대로 승격하는 릴리스 절차를 추가합니다. CLI 버전과 출시 일정은 Spine과 독립적으로 관리하며 새 앱의 기본 레시피는 `platform-contracts-preview`이며 코어와 선택한 플랫폼의 `@preview` 브랜치를 조회합니다. 기존 정식 레시피의 의존성은 보존합니다.

- 생성과 update에서 Preview 브랜치를 조회하고 해석한 태그 또는 pseudo-version을 go.mod에 기록합니다. 코어 `v0.7.0-preview.2`부터 선택형 Swagger UI와 ReDoc API를 사용할 수 있습니다. 생성 앱의 문서 UI는 별도로 활성화합니다.
- 기존 `platform-contracts-v0.7.0-preview.1` 레시피는 코어 `.1` 고정을 유지합니다. `.2`로 전환하려면 recipe를 명시적으로 바꾸고 update의 dry-run과 base hash를 검토해 적용합니다.
- Preview 코어의 출처별 입력 DTO와 경로 키를 검사하고, 중복 DTO와 키 충돌, Deprecated API 혼용을 진단합니다. 새 Preview 앱의 경로 입력 템플릿은 구조체 포인터를 사용합니다.
- `contract export --format openapi --source runtime`으로 공개 코어의 런타임 명세를 내보낼 수 있습니다. 기본값은 static이며, 런타임 모드는 composition 코드와 Go 도구를 실행하지만 리스너를 시작하지 않습니다.
- Preview 의존성을 포함한 레시피의 정식 CLI 발행은 기존 정책대로 거부합니다.
- 공개 설치한 CLI는 실제 태그 또는 pseudo-version을 표시합니다. 로컬 빌드는 `0.4.3-dev`로 구분합니다.
- `release-plan.json`에 소스 트리와 레시피 해시를 기록하고 세 OS의 설치 검증과 승인을 거쳐 태그를 만듭니다. 태그 후 공개 설치 검증 결과는 `release-manifest.json`의 `validation.reports`에 기록합니다.
- Preview와 RC는 태그와 Actions 검증 기록을 남기며, GitHub Release는 Production에서만 발행합니다.
- `run`은 SIGINT와 SIGTERM을 받아 자식 앱의 종료를 기다립니다. `dev`의 재시작과 종료도 같은 대기 정책을 사용합니다.
- 정상 종료의 기본 대기 시간은 15초입니다. `SPINE_CLI_SHUTDOWN_TIMEOUT=30s`처럼 양의 duration을 지정할 수 있습니다. 시간 초과로 강제 종료하면 로그를 남기며 CLI 종료 요청에서는 실패 코드로 구분합니다.
- 생성 HTTP 앱은 `EnableGracefulShutdown`을 활성화합니다. 기존 프로젝트에는 이 옵션을 별도로 적용해야 하며 `update`는 앱 소스를 수정하지 않습니다.

Windows의 자식 프로세스 종료는 기존 강제 종료 fallback을 유지합니다. Unix 신호 기반 graceful shutdown과 같은 보장을 제공하지 않습니다. CLI를 이전 버전으로 재설치해도 앱 소스와 의존성 파일은 자동으로 복구되지 않습니다.

발행 계획의 태그, 릴리스 노트 초안과 검증 결과를 검토하고 해당 채널의 승인 환경에서 승인합니다. 정식 릴리스의 실제 검증 결과는 첨부 manifest를 기준으로 확인하세요.

- 기존 Preview 1, Preview 2와 정식 레시피의 고정 버전은 유지합니다. `--skip-install`도 Preview 버전 조회에는 Go와 네트워크 또는 프록시 캐시가 필요하며 설치와 빌드만 생략합니다.
