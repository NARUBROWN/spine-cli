# v0.4.3-preview.15: Registry와 Group 라우트 계약 통일

다음 Preview 후보는 `v0.4.3-preview.15`입니다. `Registry`와 `Group`의 HTTP 라우트 호출을 `path, handler, options...` 순서로 통일한 코어 계약을 정적 분석합니다. 이 후보의 릴리스 태그와 공개 검증은 아직 진행하지 않았습니다.

- `Group.GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`에서 핸들러를 두 번째 인자로 읽고 이후의 `api.Tags`, `api.Summary`, `api.Description`, `api.Interceptors`를 직접 해석합니다.
- 그룹에서 상속한 메타데이터와 라우트별 옵션을 순서대로 합칩니다.
- `Registry` 라우트에서도 같은 API 옵션을 정적 계약과 OpenAPI에 반영합니다.
- 코어 `v0.7.0-preview.9`까지의 `api.Options(...), handler` 호출도 계속 분석합니다. 새 호출 순서는 코어 `v0.7.0-preview.10` 이상을 대상으로 합니다.
- 기존 `route.WithInterceptors(...)` 호환 경로를 유지합니다.

## Preview 14: 다중 스칼라 경로 입력

`v0.4.3-preview.14`는 공개됐고 Publish Preview 실행 `42496320213`이 성공했습니다. 아래 항목은 해당 후보의 기록입니다.

- `/:id/:name`은 Path 인자 등장 순서의 `input.Path[int64]`, `input.Path[string]`에 대응합니다. Context, Query와 Body 인자는 Path 순서에서 제외합니다.
- 경로 키와 스칼라 Path 인자 수가 다르면 `HTTP_PATH_SCALAR_AMBIGUOUS`를 반환합니다.
- 스칼라 Path와 직접 Path DTO 또는 Deprecated path wrapper를 섞으면 `HTTP_PATH_INPUT_MIXED`를 반환합니다.
- `input.Path[struct]`는 거부하고 기존 `*DTO`의 `path` 태그 방식은 호환 경로로 유지합니다.
- 정적 OpenAPI는 대응한 각 경로 키에 required path parameter와 스칼라 타입 및 정수 범위를 생성합니다.
- 단일 스칼라 Path는 코어 `v0.7.0-preview.8` 이상, 다중 스칼라 Path는 `v0.7.0-preview.9` 이상에서 지원합니다. 알려진 이전 코어 조합은 정적 계약 검사에서 거부합니다.

## Preview 13: 의존성 채널 선택과 영어 CLI

`v0.4.3-preview.13`은 공개됐고 Publish Preview 실행 `42484522100`이 성공했습니다. 아래 항목은 해당 후보의 기록입니다.

- 대화형 생성의 첫 단계에서 `Preview`, `RC`, `Main (release)` 중 하나를 선택합니다. 기본값은 Preview입니다.
- 비대화형 생성은 `--channel preview|rc|main`을 지원합니다. Preview는 `@preview` 브랜치, RC는 공개 RC 또는 더 높은 정식 태그, Main은 공개 정식 태그만 선택합니다.
- 선택한 값은 `spine.toml`의 `dependency_channel`에 기록합니다. `spine update`는 같은 채널을 유지하고, 키가 없는 기존 `platform-contracts-preview` 프로젝트는 Preview로 해석합니다.
- HTTP, event, WebSocket, validator와 외부 frontend provider는 모두 선택한 채널을 사용합니다. 필요한 버전이나 저장소가 없으면 프로젝트 파일을 게시하기 전에 실패합니다.
- `spine new`, `spine update`, `spine g`의 직접 출력과 도움말을 영어로 통일합니다. 생성 README, 첫 API 가이드와 저장소 문서는 한글을 유지합니다.
- Preview 발행 계획도 기본 Go proxy 환경에서는 이동 브랜치를 직접 조회해 CLI가 생성하는 의존성과 같은 버전을 고정합니다. 사용자 지정 proxy는 그대로 유지합니다.

## Preview 12: 프론트엔드 provider와 React CSR 정적 빌드

`v0.4.3-preview.12`는 공개되었고 Linux, macOS, Windows 공개 설치와 생성 앱 검증을 통과했습니다. 아래 항목은 해당 후보의 기록입니다.

- `spine new`는 터미널에서 HTTP, event, WebSocket, validator, frontend 사용 여부를 순서대로 묻고 frontend 사용 시 provider를 추가로 선택합니다. 선택 번호, 이름 검색, provider 이름 직접 입력을 지원하며 `--interactive`와 `--no-interactive`로 prompt를 제어합니다.
- 내장 React provider는 설정된 `frontend_root` 안의 `src/main.tsx`, `src/main.jsx`, `src/main.ts`, `src/main.js`를 엔트리로 자동 감지하며 경로를 사용자 설정으로 지정할 수 있습니다. 설정 없는 기존 프로젝트의 자동 감지는 지원하는 Echo 또는 `net/http` 조립에서만 적용합니다.
- frontend를 선택하지 않은 신규 프로젝트는 `frontend_enabled = false`를 기록해 이후 디렉터리 추가로 자동 활성화되지 않게 합니다. 기존 프로젝트에서 frontend 설정을 생략한 경우의 자동 감지는 유지합니다.
- 외부 frontend provider는 `github.com/NARUBROWN/spine-frontend-<provider>@preview`에서 `spine-frontend.json`을 읽습니다. `spine.frontend/v1` 선언형 설정은 esbuild engine, entry 후보, loader, npm dependency와 시작 파일을 정의하며 provider module 코드는 실행하지 않습니다.
- `frontend_root`는 `spine new --frontend-root <path>` 또는 `spine.toml`로 지정할 수 있으며 기본값은 `frontend`입니다.
- `spine dev`는 시작할 때 프론트를 빌드하고 변경된 파일을 감시해 다시 빌드합니다. 프론트 파일만 바뀌면 Go 앱은 재시작하지 않습니다. `spine run`과 `spine build`는 production 번들을 생성합니다.
- Echo 또는 `net/http` 조립에 정적 파일 서빙과 확장자 없는 HTML 경로의 SPA fallback을 추가합니다. 백엔드 라우트와 `frontend_api_prefix`는 유지하고, 존재하지 않는 asset은 404를 반환합니다.
- esbuild Go API v0.28.2를 사용합니다. Go와 npm 의존성의 라이선스 고지를 제공하고 번들에 연결된 법적 주석을 보존합니다.
- Spine이 관리하지 않는 비어 있지 않은 `frontend_output` 디렉터리는 덮어쓰지 않습니다.

## Preview 11: 단일 경로 입력 정적 분석

이번 후보는 `v0.4.3-preview.11`이며 코어 `v0.7.0-preview.8` 후보의 단일 스칼라 경로 입력을 대상으로 합니다. 두 후보의 공개 발행과 조합 검증은 아직 완료하지 않았습니다. 기존 태그는 이동하거나 재사용하지 않습니다.

- 단일 경로 값의 `input.Path[int64]` 같은 기본 스칼라와 타입 별칭을 정적 계약과 OpenAPI에 반영합니다.
- 경로 키의 수, 중복 선언과 기존 입력 API 혼용을 검사하고, 고정 크기 정수 범위를 보존합니다. 플랫폼에 따라 범위가 달라지는 타입은 미해결로 표시합니다.
- 코어 `v0.7.0-preview.7` 이하는 해당 입력을 지원하지 않아 거부합니다. 교체된 코어와 지원 여부를 확인할 수 없는 버전은 경고합니다.
- 런타임 export는 새 컨트롤러를 자동으로 준비하지 않으며 기존 `ErrRoutesNotCollected` 경계를 유지합니다.

## Preview 8: 컨트롤러 경로 등록과 전환 안내

`v0.4.3-preview.8`의 컨트롤러 경로 등록과 전환 안내를 유지합니다. 아래 항목은 해당 후보의 기록입니다.

- 코어 `v0.7.0-preview.7`의 기존 `app.Route` 폐기 표기와 전환 절차를 `llms.txt`에 설명합니다.
- 새 코어 대상 생성기는 컨트롤러의 `RegisterRoutes(*api.Registry)`에 경로와 콜백을 작성합니다. 기존 코어의 `route.go` 방식은 유지하며 사용자 파일을 임의로 삭제하지 않습니다.
- `app.Constructor(...)`에 `constructor.Custom`, `Repository`, `Service`, `Controller`, `Interceptor` 표식을 모읍니다. CLI는 공식 import 경로와 별칭, 생성 메서드와 역할 계약, 의존성을 분석합니다.
- `input.Path[T]`, `input.Query[T]`, `input.Body[T]`의 DTO와 외부 필드 이름을 정적 계약과 OpenAPI에 반영합니다. 수동 검증 규칙이나 동적 상태 코드를 추측하지 않습니다.
- 기존 Constructor 호출과 import 별칭을 보존하며 표식을 독립된 줄에 추가합니다. dry-run, diff, base_hash와 --if-match, 재실행 시 unchanged 동작을 유지합니다.
- 정적 분석은 생성자나 init을 실행하지 않습니다. 새 컨트롤러의 런타임 export는 준비 전 명시적 오류를 반환하며 DB 연결을 위해 Prepare를 자동 실행하지 않습니다.

Preview 8 준비 당시 로컬 소스의 race, vet, 생성 앱의 실제 HTTP와 별도 User DB E2E를 검증했습니다. 이 기록은 이번 후보의 세 OS 공개 설치, 원격 CI 또는 release-manifest 검증을 대신하지 않습니다.

## Preview 6과 7 수정

- 레거시 함수 생성자와 객체 생성자를 함께 등록할 때 반환 타입을 해석해 정상 의존성을 누락 오류로 보고하지 않습니다. 기존 공개 target 표현은 유지하며 실제 미해석과 잘못된 의존성은 계속 오류로 처리합니다.
- 선택한 코어의 인터셉터 계약이 누락됐거나 인터페이스가 아니면 패닉 대신 `COMPONENT_CONTRACT_INVALID`를 보고합니다.
- `schema`의 정적 기본 경로와 `context`의 프로젝트별 경로 차이를 문서에 명시합니다. 기존 `app.Route`와 컨트롤러 경로를 함께 사용하는 계약은 유지합니다.

## 공개 Preview 4: 이벤트와 validator 동적 조회

`v0.4.3-preview.4`의 이벤트와 validator 동적 조회 기능을 유지합니다. 기존 공개 태그는 변경하지 않습니다.

- `--event-platform [name:]provider`는 `NARUBROWN/spine-<provider>-platform@preview`, `--validator provider`는 `NARUBROWN/spine-validator-<provider>@preview`를 조회합니다.
- 선택 버전의 `spine-platform.json`에서 생성자, 설정 필드와 최소 Go 버전을 읽습니다. 새 provider는 메타데이터 규칙을 따르면 CLI 수정 없이 연결할 수 있습니다.
- 저장소/Preview 조회 실패와 메타데이터 누락을 구분해 경로와 원인을 표시합니다. 조회 실패는 프로젝트 파일을 만들기 전에 끝납니다.
- NATS JetStream 생성 앱과 미등록 이벤트 및 설정형 validator의 실제 브로커 E2E를 CI 필수 검사에 추가합니다. 기존 Kafka, RabbitMQ와 playground의 메타데이터 없는 버전은 호환 경로를 유지합니다.
- NATS 플랫폼의 첫 출시 후보는 `v0.1.0-preview.1`입니다. CLI의 Preview 조회는 태그 유무와 별개로 현재 `@preview`의 정규 버전을 기록합니다.

## 기존 후보와 동작

Preview CLI는 `go install github.com/NARUBROWN/spine-cli/cmd/spine@preview`로 설치할 수 있습니다. Go가 해석한 태그 또는 pseudo-version을 표시하며 로컬 빌드는 `0.4.3-dev`로 구분합니다.

`v0.4.3-preview.1`은 공식 설치 경로와 생성 문서의 명령 표기 회귀로 폐기했습니다. 해당 원격 태그를 삭제했으며 재사용하지 않습니다. 이전 후보는 `go install github.com/NARUBROWN/spine-cli/cmd/spine@v0.4.3-preview.3`로 설치하고 `spine`으로 실행합니다.

Preview, RC, Production을 순서대로 승격하는 릴리스 절차를 추가합니다. CLI 버전과 출시 일정은 Spine과 독립적으로 관리하며 새 앱의 기본 레시피는 `platform-contracts-preview`이며 코어와 선택한 플랫폼의 `@preview` 브랜치를 조회합니다. 기존 정식 레시피의 의존성은 보존합니다.

- 생성과 update에서 Preview 브랜치를 조회하고 해석한 태그 또는 pseudo-version을 go.mod에 기록합니다. 코어 `v0.7.0-preview.2`부터 선택형 Swagger UI와 ReDoc API를 사용할 수 있습니다. 생성 앱의 문서 UI는 별도로 활성화합니다.
- 기존 `platform-contracts-v0.7.0-preview.1` 레시피는 코어 `.1` 고정을 유지합니다. `.2`로 전환하려면 recipe를 명시적으로 바꾸고 update의 dry-run과 base hash를 검토해 적용합니다.
- Preview 코어의 출처별 입력 DTO와 경로 키를 검사하고, 중복 DTO와 키 충돌, Deprecated API 혼용을 진단합니다. 새 Preview 앱의 경로 입력 템플릿은 구조체 포인터를 사용합니다.
- `contract export --format openapi --source runtime`으로 공개 코어의 런타임 명세를 내보낼 수 있습니다. 기본값은 static이며, 런타임 모드는 composition 코드와 Go 도구를 실행하지만 리스너를 시작하지 않습니다.
- Preview 의존성을 포함한 레시피의 정식 CLI 발행은 기존 정책대로 거부합니다.
- 공개 설치한 CLI는 실제 태그 또는 pseudo-version을 표시합니다. 로컬 빌드는 `0.4.3-dev`로 구분합니다.
- `release-plan.json`에 소스 트리와 레시피 해시를 기록하고 세 OS의 설치 검증과 승인을 거쳐 태그를 만듭니다. 태그 후 공개 설치 검증 결과는 `release-manifest.json`의 `validation.reports`에 기록합니다.
- Preview와 RC는 태그와 Actions 검증 기록을 남기며, GitHub Release는 Production에서만 발행합니다.
- `run`은 SIGINT와 SIGTERM을 받아 자식 앱의 종료를 기다립니다. `dev`의 재시작과 종료도 같은 대기 정책을 사용합니다.
- 정상 종료의 기본 대기 시간은 15초입니다. `SPINE_CLI_SHUTDOWN_TIMEOUT=30s`처럼 양의 duration을 지정할 수 있습니다. 시간 초과로 강제 종료하면 로그를 남기며 CLI 종료 요청에서는 실패 코드로 구분합니다.
- 생성 HTTP 앱은 `EnableGracefulShutdown`을 활성화합니다. 기존 프로젝트에는 이 옵션을 별도로 적용해야 하며 `update`는 앱 소스를 수정하지 않습니다.

Windows의 자식 프로세스 종료는 기존 강제 종료 fallback을 유지합니다. Unix 신호 기반 graceful shutdown과 같은 보장을 제공하지 않습니다. CLI를 이전 버전으로 재설치해도 앱 소스와 의존성 파일은 자동으로 복구되지 않습니다.

발행 계획의 태그, 릴리스 노트 초안과 검증 결과를 검토하고 해당 채널의 승인 환경에서 승인합니다. 정식 릴리스의 실제 검증 결과는 첨부 manifest를 기준으로 확인하세요.

- 기존 Preview 1, Preview 2와 정식 레시피의 고정 버전은 유지합니다. `--skip-install`도 Preview 버전 조회에는 Go와 네트워크 또는 프록시 캐시가 필요하며 설치와 빌드만 생략합니다.
